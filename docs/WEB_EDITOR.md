# Веб-редактор: гибридная схема разработки и доставки

## Зачем гибрид

Две крайности плохи. Внешнее приложение на ПК или в облаке требует сети и ломается в
гараже без интернета. Писать UI редактора «внутри прошивки» невозможно итеративно:
каждая правка кнопки = пересборка и перезаливка прошивки.

Гибрид даёт быструю итерацию при разработке и полную автономность у пользователя,
причём код один и тот же.

## Структура репозитория

```
firmware/ (src, include, lib)   прошивка
web/                            исходники редактора (Vite + React + TS)
shared/schema/                  Zod-схема лейаута и профиля — источник истины
data/                           образ LittleFS: cars, layouts, www (собранный редактор)
docs/schema/*.json              JSON Schema, сгенерированная из Zod
```

## Режим разработки

`npm run dev` поднимает Vite на `http://localhost:5173` с горячей перезагрузкой. В
`vite.config.ts` прописан прокси: всё, что идёт на `/api` и `/ws`, уходит на реальное
устройство.

```ts
// web/vite.config.ts
const DEVICE = process.env.VITE_DEVICE ?? '192.168.4.1'
export default defineConfig({
  server: {
    proxy: {
      '/api': { target: `http://${DEVICE}`, changeOrigin: true },
      '/ws':  { target: `ws://${DEVICE}`,   ws: true },
    },
  },
})
```

В браузере открыт localhost, а данные живые с железки: телеметрия по WebSocket, чтение
и запись конфигов по REST. Прошивку при правках интерфейса перезаливать не нужно.

Плюс mock-режим: при `VITE_MOCK=1` тот же клиент подменяется генератором сигналов
(синус для оборотов, прогрев ОЖ, шум на давлении масла). Можно рисовать и отлаживать
лейауты вообще без устройства и без машины — это же используется в предпросмотре
редактора.

## Продакшн-сборка

```
npm run build      Vite собирает статику в web/dist
npm run deploy:fs  gzip + копирование в data/www
pio run -t uploadfs  сборка образа LittleFS из data/ и заливка в раздел флеша
```

Файлы кладём уже сжатыми (`index.html.gz`, `assets/*.js.gz`). Сервер на устройстве при
запросе `/assets/app.js` отдаёт `app.js.gz` с заголовком `Content-Encoding: gzip` —
экономим и флеш, и время загрузки страницы через Wi-Fi точки доступа. Позже тот же
образ обновляется по OTA через сам редактор, без USB.

Бюджет: раздел LittleFS ~7.9 МБ, сборка редактора со сжатием — порядка 200–400 КБ.
Запас огромный, места хватит и на шрифты, и на картинки пресетов, и на логи.

## Как пользователь это видит

Устройство поднимает точку доступа `Tracraft-Dash`. Телефон или ноутбук подключается к
ней и открывает `http://192.168.4.1`. Если устройство настроено на домашнюю сеть — оно
же доступно по `http://tracraft.local` через mDNS. Никакого интернета не требуется ни
на одном шаге.

## Единая схема как источник истины

Схема лейаута описана один раз на Zod в `shared/schema`. Из неё получаем:

- TypeScript-типы для редактора;
- JSON Schema (`docs/schema/*.json`) для валидации файлов и подсказок в IDE;
- сгенерированный C++ заголовок с перечислением типов виджетов и ключей свойств,
  чтобы прошивка и редактор не разъехались при добавлении виджета.

Правило: новый виджет добавляется в схему, затем в TS-художника (`paint(ctx, w, v)`) и
в C++-рендерер. Если какой-то из трёх шагов пропущен, CI ругается на несоответствие
списка типов.

## API устройства (черновик)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/state` | версия прошивки, схемы, активные лейаут и профиль, состояние шины |
| GET | `/api/signals` | список сигналов активного профиля с единицами и диапазонами |
| GET/PUT | `/api/layout/{id}` | чтение и запись лейаута |
| GET | `/api/layouts` | список пресетов |
| POST | `/api/layout/{id}/activate` | сделать активным |
| GET/PUT | `/api/car/{id}` | профиль машины |
| GET/PUT | `/api/device` | Wi-Fi, яркость, единицы, разрешение передачи в шину |
| POST | `/api/ota/firmware` | загрузка прошивки |
| POST | `/api/ota/fs` | загрузка образа файловой системы |
| GET | `/api/can/sniff` | сырые кадры для режима обнаружения сигналов |
| WS | `/ws` | телеметрия 10–20 Гц, живой предпросмотр правок, алармы |

Телеметрия по WebSocket — компактные бинарные кадры (`uint16 id` + `float value` +
флаги), а не JSON: на 60 сигналах при 20 Гц это разница между ~8 КБ/с и ~90 КБ/с.
